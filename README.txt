Quick Use Slot
==============

在 Curios 的「扩展装备/饰品栏」中新增两个「快捷使用」栏位：可以放入任意物品，
按快捷键即等同于把该物品拿在主手上右键一次。其中一个栏位在按下快捷键时会自动
按住 Shift（潜行），不需要玩家自己去按。

依赖
----
* Minecraft 1.20.1
* Forge 47.x
* Curios 5.14.1+（必需）

栏位
----
| 栏位 id            | 名称             | 说明                                       |
|--------------------|------------------|--------------------------------------------|
| quick_use          | 快捷使用         | 普通右键                                   |
| quick_use_sneak    | 快捷使用（Shift）| 使用期间自动按住 Shift，即「潜行 + 右键」  |

两个栏位都用 curios:all 校验器，因此任何物品都能放入。
order 为 10000 / 10001，并带 "replace": true，用来把它们排在 Curios 列表的最后
（replace 让本模组的声明覆盖其它来源给出的 order，而不是被取较小值合并）。

快捷键
------
| 默认键位 | 对应栏位          | 名称                     |
|----------|-------------------|--------------------------|
| V        | quick_use         | 使用快捷使用栏物品       |
| B        | quick_use_sneak   | 按住shift使用的快捷栏    |

都在「选项 -> 控制 -> 快捷使用栏」里，可自由改绑。第二个按键的意思是：
把它绑成哪个键都行（比如 A），按下那个键时模组会自动按住 Shift 来使用物品 ——
你不必自己按 Shift。

使用规则
--------
完整走一遍原版右键流程，并且完全按玩家当前指向判定：
    - 指向方块：对方块使用（放方块、桶、锄头、打火石等）；
    - 指向实体：对实体交互（命名牌、拴绳、挤奶、喂食等）；
    - 指向空气：直接使用物品（末影珍珠、雪球、工具等）；
    - 食物与药水这类需要按住使用的物品会一次性完成。

quick_use_sneak 的差别只在「潜行」这一件事上：可以贴着箱子/工作台放方块而不是
打开它、对生物用物品而不是和它交互 —— 和原版按住 Shift 右键完全一致。

使用后物品的变化（消耗、耐久、空桶、玻璃瓶）会写回栏位。

已知限制
--------
* 需要蓄力的物品（弓、盾、望远镜、三叉戟）无法「快捷使用」，按快捷键不会有反应。
* 主手正在使用物品时（例如拉弓）按快捷键不会生效，与原版右键一致。
* 栏位顺序是「尽力排在最后」：order 10000 能排在所有使用默认顺序（<=1000）的模组
  栏位之后；如果别的模组也用了 10000 以上的 order，就未必是绝对最后一个。

关于整合包的 datapack 缓存
--------------------------
某些大型整合包（例如 GregTech Odyssey 的 GTOCore）会把所有 datapack 的 JSON
缓存到自己的目录里（GTO 是 gtocore/cache/json/），之后每次启动直接回放缓存，
而不是重新读一遍各个模组 jar 里的文件。

这会造成一个很隐蔽的现象：本模组的 data/quickuseslot/curios/*.json 更新了，
但 Curios 读到的仍是缓存里那份旧定义 —— 表现为栏位顺序不变、或者新加的栏位
不出现。1.0.1 时 quick_use 卡在 head 后面、quick_use_sneak 只靠 IMC 才出现，
就是这个原因。

所以更新本模组（或任何改了 datapack 数据的模组）之后，如果整合包带这种缓存，
需要删掉缓存让它重建一次，GTO 就是删掉

    minecraft/gtocore/cache/json

后重启游戏（该目录是可再生的缓存，会重新生成）。

构建
----
    gradlew build

产物位于 build/libs/quickuseslot-<版本>.jar。

开发
----
* Java 包名 com.lai.quickuseslot。
* 客户端只做两件事：注册按键、把按键转成一个数据包；其余逻辑全在服务端。
* 数据包只在按键时发送，没有任何每刻（per-tick）的扫描或轮询开销。
* 开发环境注意：build.gradle 的 run 配置里带了 mixin.env 的 refmap 重映射，
  否则 Curios 的 mixin 在 dev 工作区会启动失败。
